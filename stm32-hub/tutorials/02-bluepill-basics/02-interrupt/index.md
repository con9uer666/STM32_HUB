# 第 2 节 · 让程序自己响应：了解中断

> 本节目标：理解“不是一直轮询，而是事件来了再处理”的基本思想，并完成一次外部中断实验。

## 什么是中断

中断可以理解为：CPU 本来在做自己的事，某个事件发生后，先暂停手头工作，转去执行对应的处理函数，处理完再回来。

这比一直在 `while(1)` 里傻等高效得多。

## 最常见的入门例子

给一个按键或外部信号配置 EXTI，当电平边沿到来时切换 LED 状态。

## 配置步骤

1. 选择一个输入引脚，例如 PA0。
2. 在 CubeMX 中设置为 External Interrupt Mode。
3. 配置触发边沿，通常先选上升沿或下降沿。
4. 打开对应 NVIC 中断。
5. 生成代码，在回调里写处理逻辑。

## 典型回调写法

```c
void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
  if (GPIO_Pin == GPIO_PIN_0)
  {
    HAL_GPIO_TogglePin(GPIOC, GPIO_PIN_13);
  }
}
```

## 两个必须建立的概念

### 中断服务函数要短

中断里不要做长时间阻塞操作，更不要在里面写大量 `HAL_Delay()`。中断的职责通常是“快速响应、记录状态、通知主循环”。

### 抖动不是 bug，是物理现实

机械按键会抖动，所以一次按下可能触发多次中断。后面你需要加软件消抖或硬件滤波。

## 排查思路

- 中断没进：先检查引脚模式、边沿触发和 NVIC。
- 进了但现象不对：看回调里是否判断了正确的引脚。
- 触发多次：优先怀疑按键抖动。

## 本节小结

学会中断以后，你就从“CPU 一直主动问有没有事”切换到了“事件来了再响应”的思维方式。后面的串口接收、定时器、DMA 都会反复用到这个思路。
