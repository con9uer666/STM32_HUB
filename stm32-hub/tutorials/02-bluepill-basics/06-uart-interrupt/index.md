# 第 6 节 · 不再轮询等待：串口中断

> 本节目标：让串口在收到数据时自动通知程序，而不是一直傻等。

## 为什么串口接收很适合中断

串口数据什么时候来，往往是不确定的。如果你一直在主循环里轮询，不仅效率低，还会拖慢别的逻辑。

中断方式的思路是：

- 先挂起一次接收。
- 字节到了后进入回调。
- 在回调里处理或缓存数据。
- 再次挂起下一轮接收。

## 一个最常见的入门写法

```c
uint8_t rx_byte;

HAL_UART_Receive_IT(&huart1, &rx_byte, 1);

void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart)
{
  if (huart->Instance == USART1)
  {
    HAL_UART_Transmit(&huart1, &rx_byte, 1, 100);
    HAL_UART_Receive_IT(&huart1, &rx_byte, 1);
  }
}
```

## 这个例子想让你理解什么

- 中断回调只在“接收完成”时触发。
- 回调里要重新挂起下一次接收。
- 这种方式很适合按字节协议、命令行或简单控制帧。

## 什么时候它不够用

如果数据量很大、速率很高，或者帧长不固定，仅靠逐字节中断会带来较高 CPU 开销。这就是下一节 DMA 要解决的问题。

## 常见问题

- 只收一次：忘了在回调里重新启动接收。
- 一直进不了回调：USART 中断没开、NVIC 没配或句柄不匹配。
- 数据乱序：主循环和回调同时访问同一缓冲区，但没有管理好。

## 本节小结

串口中断的核心价值，是把“等待数据”这件事交给硬件通知机制。只要你理解了“触发 - 回调 - 重挂接收”这条链路，后面的很多通信处理都会简单很多。
