# 第 9 节 · 先约定时钟再传数据：SPI

> 本节目标：理解 SPI 的四线通信模式，知道为什么它更快，也知道为什么它更依赖时序约定。

## SPI 和 I2C 最大的区别

SPI 通常至少使用四根线：

- SCK：时钟
- MOSI：主发从收
- MISO：主收从发
- CS：片选

它不像 I2C 那样强调设备地址，而是通过片选线决定当前和谁通信。

## 为什么 SPI 常被认为更快

- 时序更直接。
- 双工能力更强。
- 协议开销相对更低。

但代价是：线更多，设备多时片选管理更麻烦。

## 入门最先要搞懂的两个参数

- CPOL：时钟空闲电平
- CPHA：数据采样边沿

如果这两个模式和从设备不一致，最典型的结果就是“有波形，但数据全错”。

## 一个简单收发示例

```c
uint8_t tx[2] = {0x9F, 0x00};
uint8_t rx[2] = {0};
HAL_GPIO_WritePin(GPIOA, GPIO_PIN_4, GPIO_PIN_RESET);
HAL_SPI_TransmitReceive(&hspi1, tx, rx, 2, 100);
HAL_GPIO_WritePin(GPIOA, GPIO_PIN_4, GPIO_PIN_SET);
```

## 调试顺序

1. 先确认片选是否真的拉低。
2. 再确认时钟模式和数据位宽。
3. 再看发送顺序和接收缓冲区。
4. 如果有逻辑分析仪，优先抓波形验证。

## SPI 适合什么场景

- Flash 存储
- 高速显示屏
- 某些高速 ADC / 传感器

## 本节小结

SPI 的核心不是 API，而是“片选、时钟模式、收发时序”三件事。把这三点搞清楚，很多外设驱动都会顺很多。
