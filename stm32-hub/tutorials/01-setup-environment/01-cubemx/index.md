# 第 1 节 · 图形化外设配置：CubeMX

> 本节目标：学会把芯片的引脚、时钟和基础外设配置成一个可生成代码的工程。

## CubeMX 到底帮你做了什么

CubeMX 不是编译器，它做的是三件事：

- 帮你选择芯片和封装。
- 帮你配置引脚复用、时钟树和外设参数。
- 生成 HAL / LL 初始化代码和工程框架。

对初学者来说，最大价值不是“自动写代码”，而是把容易配错的底层参数集中到图形界面里。

## 一个标准工程怎么创建

1. 打开 CubeMX，选择具体 MCU 或开发板。
2. 在 Pinout 界面配置需要的 GPIO、USART、TIM 等外设。
3. 在 Clock Configuration 里确认系统时钟来源和频率。
4. 在 Project Manager 中设置工程名、生成路径和工具链。
5. 点击 Generate Code。

## 初学阶段最常看的两个页面

### Pinout & Configuration

这里决定每个引脚做什么，外设开没开，参数怎么配。只要外设表现异常，先回到这里检查。

### Clock Configuration

定时器频率不对、串口波特率不准、延时乱掉，很多时候根因都在时钟树。不要把它当成“看起来能过就行”的页面。

## 建议固定下来的生成设置

- 把代码生成到独立目录，便于管理。
- 尽量保持用户代码写在 USER CODE BEGIN / END 区间内。
- 若后续还会反复改配置，不要直接在自动生成文件中大改结构。

## 一个常见习惯

每做完一次稳定配置，就保留一份 `.ioc` 文件和能编译通过的工程快照。这样以后改坏了，可以直接回退到最近可用状态，而不是从零重配。

## 最容易踩的坑

| 现象 | 常见原因 |
| --- | --- |
| 代码能生成，但编译不过 | 工具链选错或工程路径不一致 |
| 串口波特率不准 | 时钟树配置和实际晶振不符 |
| 引脚无输出 | 引脚模式、上拉下拉或复用被别的外设占用 |

## 本节小结

CubeMX 的核心不是“点按钮”，而是建立一个正确、可再生的底层配置。后面第二章的每个实验，基本都要回到这里改外设设置。
